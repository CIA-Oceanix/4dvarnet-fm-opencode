# L96 conditional sampling from a flow-matching prior

`reports/l96/generate_l96_fm_sampler_report.py` from the JSON written by
`reports/l96/run_sda_sampler_experiments.py`; the sampler itself is

## 1. The question

The scoping calls for a *sampler* baseline built on an FM prior -- a scheme that
produces a calibrated conditional ensemble -- not another conditional-mean estimator.
The benchmark's strong rows are all point estimators or mean-estimator hybrids, so
the open question is what an FM prior with observation guidance actually delivers,
and what it costs to close the accuracy gap to a discriminatively-trained mean.

## 2. A deterministic estimator is a flow

Write the FM operator as `Psi(x_tau, y) = E[x_1 | x_tau, y]`; the Tweedie identity
gives the velocity `v = (Psi - x_tau)/(1-tau)`. Take *any* deterministic estimator
`m_hat(y)` and read it as an operator that ignores its state argument:

    Psi_det(x_tau, y) = m_hat(y)    =>    v_det = (m_hat - x_tau) / (1 - tau).

Integrating `v_det` from `x_0 ~ N(0, sigma_0^2 I)` gives, exactly,

    x_tau = (1 - tau) x_0 + tau m_hat ,

which is precisely the SDEdit / warm-start state. **The warm start is not a separate
trick -- it is the trajectory of the degenerate flow whose operator is constant.** A
deterministic estimator and a generative prior therefore live in the same space and
can be mixed at the level of velocities:

    v_lam = (1 - lam(tau)) v_FM + lam(tau) v_det ,    lam(tau) = lam_0 (1 - tau)^p .

* `lam_0 = 0` is the cold (pure FM) sampler.
* `lam(tau) = 1{tau < tau_0}` -- the discontinuous member -- is exactly the warm start.
* **`p >= 1` is required.** `v_det` carries a `1/(1-tau)` factor, so the blended
  velocity contains `lam(tau)/(1-tau) = lam_0 (1-tau)^{p-1}`, bounded as `tau -> 1`
  only for `p >= 1`. This is enforced in `Blend.__post_init__`, not left to the
  caller. It is not a numerical nuisance: it says a constant operator cannot be
  blended in with fixed weight all the way to `tau = 1`, where the FM operator must
  take over.

**Why the weight should decay.** At the warm-start time the state is
`x_{tau_0} = (1-tau_0) x_0 + tau_0 m_hat`, and the FM operator's Gaussian part maps it
through the gain `K_tau = tau P / ((1-tau)^2 sigma_0^2 + tau^2 P)`. The effective
weight the final estimate places on `m_hat` is therefore `w = tau_0 K_{tau_0}` -- the
classical two-estimator combination weight, trusting the deterministic estimate in
proportion to the prior variance still unexplained at that time. Since `K_tau` rises
with `tau`, the continuous family should put its mass at small `tau`, which is what
`(1-tau)^p` does smoothly instead of the hard cut.

**Relation to the CFM literature.** Time-varying mixing of two velocity fields is
standard under another name: classifier-free guidance is
`v = (1+w) v_cond - w v_uncond`, an affine combination of two flows with a weight
implementations routinely schedule in `tau`. What is *not* standard is that one of
the two flows is a **pre-trained deterministic estimator re-read as a degenerate
flow** rather than a second generative model. That reading is what makes the warm
start a special case instead of an unrelated heuristic.

## 3. Setup and conventions

**Prior.** `SDA3_monai_cond_noisy_l96_norm`, an observation-conditional CFM trained
under noisy parameters/forcings. Linear interpolant
`x_tau = (1-tau) x_0 + tau x_1`, `x_0 ~ N(0, sigma_0^2 I)`, `sigma_0 = 0.5`.

**Guidance.** SDA-style variance-weighted likelihood guidance (Rozet & Louppe): the
Tweedie estimate `x_hat_1 = x_tau + (1-tau) v` is scored against the observations
with weights `1/(2(R + Gamma alpha_tau^2/beta_tau^2))`, `Gamma = 1e-2`, and the state
nudged by `dt alpha_tau^2/(beta_tau (1-tau))` times that gradient.

**Mean estimator.** `L1b_monai_unet_s0s1_norm_obsdensity`, the observation-density
augmented DirectUNet-M.

**Metrics.** `rmse_repo` is the repo's `evaluate_estimates` convention -- the mean
over state dimensions of the per-dimension RMSE -- and is the number comparable to
the consolidated benchmark. `rmse_pooled` pools over all entries; the two differ by
~8% on L96, so both are reported. `spread` is
`sqrt(mean over entries of the ensemble variance)` (biased, `correction=0`).

**Reliability target.** A perfectly reliable `N`-member ensemble with biased variance
has `spread/RMSE = sqrt((N-1)/(N+1))` -- 0.845 at `N = 6`, 0.905 at `N = 10`. Far
below target is over-confident; far above, over-dispersive.

## 5. Measured

### 5.1 Full test set

200 windows, `N = 30` members, `N_outer = 50`, `Gamma = 0.01`, seed 0. Reliability target **0.967**.

*Provenance: produced by the pre-refactor run_blended_flow_sampler.py (SLURM 53976); the current driver reproduces this suite exactly (see 5.2).*

| config | rmse_repo | rmse_pooled | spread | ratio |
|---|---|---|---|---|
| mean-only | 0.4714 | 0.4934 | 0.0000 | 0.000 |
| cold(lam0=0) | 0.5295 | 0.5686 | 0.6833 | 1.202 |
| warm(tau0=0.3) | 0.3978 | 0.4268 | 0.1211 | 0.284 |
| lam0=0.5,p=1 | 0.3923 | 0.4202 | 0.1597 | 0.380 |
| **lam0=0.5,p=2** | **0.3764** | 0.4051 | 0.2369 | **0.585** |


**Harness validation.** The `mean-only` row must reproduce the benchmark's
`DirectUNet-M(monai,cos,obsdensity)` = 0.4727, since it is the same checkpoint on the
same windows. It does, to 0.3%. That is what licenses comparing anything else here
to the benchmark.

**The internal result, which is the clean one.** Against its own warm-start baseline
at identical settings, the blend improves **both** axes at once: RMSE
0.3978 -> 0.3764 (**-5.4%**)
with spread 0.1211 -> 0.2369
(**+96%**). This is the one Pareto improvement in this body of
work, it holds at both ensemble sizes tested, and it is a single scalar schedule with
no retraining.

**Against the benchmark.** The blend's 0.3764 is
3.2% ahead of `DirectUNet(aug)+SDA3` = 0.3889, and at `N = 30` the member count now **matches** that
row, so ensemble size no longer explains any of the gap.

The `warm` row decomposes what remains. It is the *same scheme* as `DirectUNet(aug)+SDA3` under
this report's settings and scores 0.3978 -- **+2.3%**
against 0.3889. So this report's SDA variance-weighted guidance at the stated
`N_outer` is mildly worse than the repo's normalized-gradient DPS at
`guidance_weight = 2.0, N_outer = 10`, and the blend's own gain is what carries it
past. The honest summary is that **the blend is worth ~5% RMSE
and ~2.0x spread relative to the warm start it
replaces** -- and that this lands ahead of the benchmark row, not that the blend
improves on the benchmark by that margin.

## 6. Negative results, with diagnoses

Each was implemented, run and rejected. The diagnoses are the substantive content --
several follow from the operator decomposition rather than from implementation faults.

### 6.1 Variance-corrected warm start -- negligible

The warm-start state has second moment `(1-tau_0)^2 sigma_0^2` from the noise but
omits `tau_0^2 P_hat` from the estimator's own error. Adding it back changed nothing
(0.4744 -> 0.4767 rmse_repo, 4 windows): the missing term is `tau_0^2 P_hat = 0.011`
against `(1-tau_0)^2 sigma_0^2 = 0.123`, i.e. ~8%.

### 6.2 Operator mean-shift -- the algebra is output-only

Replacing the operator's mean directly as `Psi* = Psi(x_tau) + (1 - tau K) Delta_m`
was catastrophic (1.043 / 1.124 rmse_repo, 4 windows). The cause is **not**
out-of-distribution network queries, which was the first and wrong guess. The update
is *output-only* and valid only if `Psi` is affine. The correct mean-shifted operator
shifts the input too:

    Psi*(x_tau) = Delta_m + Psi(x_tau - beta_tau Delta_m)
    =>  v*(x_tau) = v(x_tau - beta_tau Delta_m) + Delta_m ,

which integrates to shifting the whole trajectory -- i.e. reduces **exactly** to
post-hoc addition of `Delta_m`. There is nothing to gain from doing it inside the ODE.

### 6.3 Post-hoc recentering and a diagonal covariance update

Recentering the ensemble on `m_hat` gives the mean-only RMSE by construction (0.5547,
4 windows) while keeping the cold sampler's spread -- ratio 1.145, over-dispersive,
since the sampler's spread reflects *its* error, not the better estimator's. The
diagonal covariance update applied on top brings the ratio to 0.801 (spread
0.6743 -> 0.4721). This works, and is the cheapest route to a calibrated ensemble
around a good mean, but it is a two-stage construction rather than a sampler: the
RMSE is entirely `m_hat`'s.

### 6.4 Low-rank / iterative covariance -- rank deficiency

Replacing the diagonal target with `Sigma_hat = (1-lam)D + lam A A^T` (ensemble
anomalies rescaled so `diag(Sigma_hat) = p_hat`, applied by Woodbury) *inflated*
rather than calibrated: ratio 0.854 -> 1.964 at `lam = 0.1`, 1.190 -> 2.187 at
`lam = 0.5`, and iterating did not recover. With `N = 6` members in a
72000-dimensional state the sample covariance is hopeless -- the ensemble contributes
sampling noise, not correlation structure. Localisation is the standard remedy and
was not pursued.

### 6.5 Desroziers innovation calibration -- the estimator fits the observations

Truth-free calibration via `E[d_oa . d_ab] = H A H^T` drove the spread monotonically
down (1.145 -> 0.660 over 3 iterations), past the target rather than onto it. The
diagnostic assumes the analysis error is independent of the observation noise, but
`m_hat` is *trained to fit the observations*, so its departures understate its error:
measured `dep_fit = 0.147` against a known `R = 0.163`. The diagnostic is being fed a
quantity it is not valid for.

Two implementation faults found and fixed en route, both worth remembering: computing
the update from the fitted departure `||y - H x_bar_a||^2` instead of the Desroziers
product, and computing the diagnostics on the *recentered* ensemble, which erases the
very dependence being iterated on.

### 6.6 Observation cross-validation -- brittle under temporal holdout

Holding out 25% of observed timesteps restores the independence 6.5 lacks, at the
cost of feeding `m_hat` a thinned observation set it was not trained for. The
resulting error estimate over-shoots by ~15x, so the calibrated ensemble is wildly
over-dispersive: ratio 1.145 -> 1.692 (un-augmented mean) and 1.212 -> 2.040
(obsdensity-augmented mean -- *worse*, since that model exploits density even more).
The bias direction is the safe one; the magnitude makes it useless.

### 6.7 Decoupled mean / gain / non-Gaussian control -- `Psi_NG` is not invariant

The blend moves three things at once. In the operator decomposition,

    Psi_lam = [(1-lam) mu_p + lam m_hat] + (1-lam) K_p (x - beta mu_p) + (1-lam) Psi_NG

so blending toward a better mean also shrinks the gain *and* the non-Gaussian term --
which is where the dispersion goes. Giving each component its own knob should
therefore recover the RMSE gain without the spread loss. It does not (see the table
in §5): worse on **both** axes.

The cause is a caveat flagged when the unified form was derived, then underweighted:
`Psi_NG` is *defined relative to the pair* `(mu_p, K_p)` -- it is the residual of the
network's operator after subtracting that specific affine part. Re-using the
network's `Psi_NG` beneath a different gain `K~` is inconsistent, and the
inconsistency dominates. Real decoupling would require retraining `Psi_NG` against
the new affine part, which is precisely the argument for the unrolled-mean
architecture in `docs/results/cfm_affine_velocity_decomposition.md` §5.

## 7. Conclusions

* An FM prior with variance-weighted guidance **is** a working conditional sampler.
  The cold configuration is the closest to reliable of anything measured here, and
  its RMSE (0.5295) beats Strong-4DVar (0.8116) by
  35% and both ensemble DA baselines by more -- same
  `rmse_repo` convention, same 200 windows.
* It is **not** calibrated. It is consistently over-dispersive by roughly a fifth to
  a quarter, at every ensemble size tested: ratio/target = 1.20 at `N = 6`
  (1.014/0.845), 1.22 at `N = 10` (1.104/0.905) and 1.24 at `N = 30` (1.202/0.967).
  That the miss is stable across `N` says it is a property of the sampler, not of the
  ensemble size. Earlier in this investigation the cold configuration was described
  as "calibrated"; that reading is withdrawn.
* It does not reach the accuracy of a discriminatively-trained mean estimator, let
  alone the benchmark hybrids. Every scheme that closes that RMSE gap does so by
  importing the mean estimator, and pays for it in spread.
* The blended-flow family is the best trade found: one scalar schedule, no
  retraining, strictly dominating the warm start it replaces on **both** axes.
* **We do not have a sampler that is simultaneously benchmark-competitive on RMSE and
  calibrated.** That is the honest state of the question.
* The negatives point away from post-hoc surgery and toward *training*: §6.7 shows
  the non-Gaussian term cannot be re-used beneath a changed affine part, which is the
  argument for learning `Psi_NG` against a prescribed `(mu, K)`.

**Three hazards baked into the code rather than left to the reader.**

1. `estimate_prior_gain_variance` takes **no** `guidance` argument. `P_prior` must be
   measured on an unguided pass; doing it on a guided ensemble gives 0.153 instead of
   0.804 and silently moves a calibration ratio from 0.854 to 1.190. That mistake was
   made three separate times during this work, so the unguided integration is inlined
   and there is no flag left to forget.
2. `sample` draws exactly one `torch.randn` per member, in member order, before that
   member's trajectory, and the scheme classes have no access to the RNG. Reordering
   those draws changes every number while still looking plausible.
3. `prior_mean` takes a `seed` and seeds before drawing. It previously used the
   ambient generator, which made `mu_p` -- and therefore every `Decoupled` row --
   vary run to run (0.6098 / 0.6102 / 0.6113 for `decoup a0=.5` across three runs of
   identical code). It hid well: `estimate_prior_gain_variance` seeds internally and
   each scheme's `sample` is preceded by `torch.manual_seed`, so `P_prior` and all
   the blend rows were bit-for-bit stable, and only `Decoupled` reads `mu_p`. The
   whole suite now reproduces exactly across runs; `tests/test_fm_sampler.py` asserts
   `prior_mean` is independent of the ambient RNG state.
