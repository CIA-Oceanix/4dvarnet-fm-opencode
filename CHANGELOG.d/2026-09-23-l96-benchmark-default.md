## 2026-09-23: L96 benchmark default preset -- random observing system, fixed random validation, training seed

**Summary:** New preset `config/l96_benchmark_default.yaml` (on top of `lorenz96_default`, which is left untouched): the P1 recipe (monai, normalize, cosine, 400 epochs, lr 1e-3, clip 10, batch 16) with training obs from a random observing system redrawn every batch -- 10-300 stratified obs times, step 0 always observed, 4-16 fast channels per window (subset per obs time), slow channels always. Validation windows are re-observed once, with a fixed seed, from the same distribution, so `val_loss` and `stage1_best` selection measure a random layout instead of the regular grid. Evaluation reports both the regular 30-obs set and the random 30-obs / 8-fast set. First two experiment configs: `L96B_directunet_monaiM`, `L96B_vanillacfm_monaiM`.
**Files modified:** `config/l96_benchmark_default.yaml`, `config/experiment/L96B_{directunet,vanillacfm}_monaiM.yaml` — new; `data/obs_times.py` — `first_step` in `resample_obs_variable`, `reobserve_windows_fixed`; `data/dataloader.py` — `first_step` pass-through; `train.py` — `data.obs_first_step`, `data.val_obs_random_layout`, optional `training.seed` (`seed_everything` after data generation); `conf/schema.py` — the new fields, all off by default; `tests/test_l96_obs_times.py` — 3 new tests.
**Rationale:** Frozen per-window training obs (P1) are an artefact: fresh noise alone improves DirectUNet-M by 14%, random times by a further 8%, and a regular-only test hides a 3.6-4x degradation under a changed observing system. Validation on the regular grid would bias checkpoint selection back toward it. Existing configs are unaffected (every new flag defaults off).
**Verification:** `pytest tests/test_l96_obs_times.py tests/test_l96_normalization.py` — 34 passed; `ruff check` clean; both configs compose identically to the tested `*_obslayout300_l96` runs apart from the intended fields; 2-epoch smoke train+eval of both; same `training.seed` reproduces losses exactly.
