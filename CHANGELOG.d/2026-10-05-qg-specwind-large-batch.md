## 2026-10-05: QG gyrostat neural training — batch-16 / batch-64 protocol for G1-L

**Summary:** `train_qg_neural.py` now reads the training budget and loader settings from the experiment YAML (`training.epochs`, `training.batch_size`, `training.num_workers`, `data.regen_every`; CLI flags still override), records the regeneration spacing in `resolved_config.yaml`, and the training sbatch stops hard-coding batch 2 / 4 workers / regen every 5. New configs `G1L_direct_unet_tchannels_specwind_b16.yaml` and `_b64.yaml`: batch 16 or 64, 1200 epochs (75k / 19k optimizer steps), peak LR 5e-4 with a 40-epoch warm-up then cosine, a fresh 1000-window round every 30 epochs (40 rounds, as at batch 2), 10 data workers.
**Files modified:** `train_qg_neural.py`; `batch/run_qg_specwind_neural_train.sbatch`; `config/experiment/G1L_direct_unet_tchannels_specwind_b{16,64}.yaml`; `tests/test_qg_neural.py`.
**Rationale:** Batch 2 was inherited from the legacy Q1 recipe (an older, memory-limited backbone). Measured on an L40S: per-sample GPU cost falls 4-5x from batch 2 to 16 (G1-L 18.3 → 8.2 ms/sample, 4.6 GB at batch 16), while the CPU data pipeline (~206 ms per fresh sample on one core) already dominated the batch-2 epoch, hence 10 workers. Batch 16 × 1200 epochs matches the L96 benchmark's budget (1000 windows per epoch, batch 16). b64 keeps the same peak LR so the comparison isolates the batch. Every pre-existing YAML already states the old code defaults (epochs 200/400 by model type, batch 2), so reading them changes no earlier run.
**Verification:** `pytest tests/test_qg_neural.py tests/test_qg_config_persistence.py tests/test_qg_specwind_neural.py` (111 passed): the b16/b64 configs differ from G1-L only by the budget, the CLI budget flags default to None; launched G1-L b16 / b64 and checked their resolved configs.
