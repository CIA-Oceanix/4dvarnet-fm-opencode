## 2026-09-29: SLURM scripts keep scratch files on /SCRATCH and clean them up

**Summary:** 161 batch scripts set `MPLCONFIGDIR=/tmp/mplconfig_<job>` on the node's root disk and never removed it. None set `TMPDIR`, so Python / DataLoader temporary files (`pymp-*`) also went to the root-disk `/tmp`. They now use a per-job directory on the node-local `/SCRATCH` disk, falling back to a per-job `/tmp` directory if `/SCRATCH` is missing. Both `TMPDIR` and `MPLCONFIGDIR` point into it, and a `trap ... EXIT` removes it when the job ends.
**Files modified:**
- `batch/*.sbatch` (161 files) — the one-line `export MPLCONFIGDIR="/tmp/mplconfig_..."` is replaced by the two-line `NODE_TMP` snippet. It is self-contained, so the scripts that `cd` into other worktrees need no shared helper. `run_l96_rank_histograms.sbatch` already had its own temp dir and trap and is unchanged.
- `tests/test_batch_node_tmp.py` (new) — no script uses `/tmp/mplconfig_*`; every script with `NODE_TMP` exports `TMPDIR` and cleans it up.
**Rationale:** On 2026-09-29 the root filesystem of sl-mee-br-207 (98 GB, which also holds `/tmp`) was 100% full. About 25 GB of it is not visible to users, likely container storage or files held by other users' sessions; this needs the cluster admins. DataLoader workers then failed with ENOSPC, and FDV2 subgrad-M (job 56309_6) hung for ~15 h at epoch 938. Our own `/tmp` usage there was small (~300 MB of leftover `mplconfig_*`), but a job should not depend on the root disk having space.
**Verification:** `bash -n` on every changed script; the snippet was run under `set -euo pipefail` in both the `/SCRATCH` and the fallback case (Python's `tempfile.gettempdir()` points into it, and the directory is removed at exit); `pytest tests/test_batch_node_tmp.py`.
